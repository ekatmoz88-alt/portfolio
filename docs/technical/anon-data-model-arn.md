# Абстрактная модель данных и структура БД

*Документ представляет собой анонимизированную выжимку из ER-модели крупной реестровой системы.*

## Ядро модели (Сущности)
1. **Субъект (Person/Org):** Ключевой блок учета физических и юридических лиц. Связка через СНИЛС/ИНН (хэширование/токенизация в рамках NDA).
2. **Документы (Document):** Серия, номер, тип документа, статус действия, дата выдачи/окончания. Историчность изменений.
3. **Адресный блок (Address/FLC):** Привязка к ФИАС/КЛАДР, история перемещений.
4. **Статусы и Жизненный цикл:** Машина состояний (FSM) для учетных записей.

## Масштаб и реализация
- **Объем:** ~290 таблиц (экспорт из Sybase PowerDesigner).
- **Нормализация:** 3НФ (Третья нормальная форма) с выделением справочников (типы, статусы) в отдельные таблицы.
- **Индексы:** Покрывающие индексы на часто запрашиваемые поля (поиск по документам, ФИО).
- **Историчность:** Реализация через версионность (valid_from / valid_to) либо триггеры аудита (log-таблицы).

## Особенности БД
- Высоконагруженная система (Highload) с требованиями к консистентности данных.
- Разграничение доступа на уровне строк/схем (RLS/Роли БД).
