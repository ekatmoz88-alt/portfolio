# Архитектура и интеграции системы

*Анонимизированное описание архитектуры корпоративного контура и взаимодействия с внешними системами.*

## Топология
- **Ядро:** Реляционная СУБД (кластер Master-Slave / Sharding).
- **Сервисный слой:** REST/SOAP API шлюзы для внутренних модулей.
- **Клиентская часть:** Web-интерфейс (тонкий клиент), интеграция с ЕСИА/ЕСИА-подобными системами.

## Межведомственный обмен
- **Протоколы:** Защищенные каналы (VPN/TLS), асинхронный обмен через шину (Message Broker / MQ).
- **Форматы:** XML/JSON (регламентированные схемы XSD), трансформация данных (ETL/ELT).
- **Безопасность:** Электронная подпись (ЭП/EDS) на уровне сервисов и документов, шифрование чувствительных атрибутов.

## Требования и Регламенты
- Соблюдение 152-ФЗ (персональные данные), требования ИБ (КСЗ, УЦ).
- SLA на доступность (99.5%+) и время обработки транзакций.
- Резервное копирование (полное/инкрементальное), сценарии Disaster Recovery (DR).

## Аналитический вклад
- Проектирование логической/физической моделей (PDM/LDM).
- Написание ТЗ на интеграционные API и регламенты обмена.
- Контроль миграций схемы БД (версионность через Liquibase/Flyway или скрипты).
