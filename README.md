# REST API / OpenAPI Documentation Portfolio

**Role:** Senior Technical Writer  
**Focus:** REST API · OpenAPI 3.x · Developer Documentation · Docs-as-Code

## 📌 Overview
A demonstration portfolio documenting a fictional **Orders API** from scratch — built to showcase real-world API documentation practices for developers and integrators.

## 📂 Repository Structure
| File / Folder | Description |
|---------------|-------------|
| `openapi/openapi.yaml` | OpenAPI 3.1 specification: endpoints, parameters, schemas |
| `docs/endpoint-reference.md` | Endpoint reference with request/response examples |
| `docs/error-codes.md` | HTTP status codes & error models |
| `docs/webhooks.md` | Webhook events, payloads, retry logic |
| `docs/developer-guide.md` | Onboarding guide for integrators |
| `docs/changelog.md` | Versioned changelog (Docs-as-Code style) |
| `README.ru.md` | 🇷🇺 Russian version |

## 🛠 Tech Stack
`REST API` · `OpenAPI 3.1` · `JSON` · `Postman` · `Git` · `Markdown` · `Webhooks` · `Docs-as-Code`

## ✨ Approach
- **Single Source of Truth**: spec-driven documentation
- **Docs-as-Code**: sources in Git, versioned with changelog
- **Developer-first**: copy-pasteable request/response samples
- **Bilingual**: EN (this file) + RU (`README.ru.md`)

> ⚠️ The Orders API is illustrative. The documentation structure, schemas, and workflows reflect production-grade practices.
